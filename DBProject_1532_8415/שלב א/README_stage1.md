## 1. אודות המערכת ומטרת הפרויקט

פרויקט זה עוסק באפיון, תכנון הנדסי, מידול ומימוש של בסיס נתונים רלציוני מתקדם לניהול מערך **כוח האדם ומשאבי האנוש** במכללה אקדמית (הותאם לפעילות במרכז האקדמי לב - JCT).

מטרת המערכת היא לייצר מאגר מידע מרכזי, אמין, מנורמל (לפחות ברמת 3NF) ומוגן באילוצי שלמות נתונים, המאפשר:
- ניהול עובדים מלא ומדויק תוך הפרדה מבנית בין מסלול אקדמי למסלול מנהלי.
- מעקב תקציבי וארגוני לפי מחלקות.
- ניהול יומני נוכחות יומיים מפורטים (שעון עבודה, שעות הגעה ועזיבה).
- מעקב הסמכות, סדנאות, קורסי בטיחות והדרכות פדגוגיות ומקצועיות של אנשי הסגל.

## 2. היחידה הארגונית והתחומים המטופלים

המערכת מספקת מענה לארבעה מודולים תפעוליים מרכזיים:

```
                          ┌──────────────────────────────────────────────┐
                          │     מערכת ניהול כוח אדם למכללה (HR)           │
                          └──────────────────────┬───────────────────────┘
                                                 │
         ┌───────────────────────┬───────────────┴───────────────┬───────────────────────┐
         ▼                       ▼                               ▼                       ▼
 1. היררכיית עובדים       2. מבנה מחלקתי                 3. יומני נוכחות          4. קטלוג הדרכות
  • סגל אקדמי (קביעות,     • מעקב תקציבי מחלקתי           • שעון כניסה ויציאה      • קורסי בטיחות
    תחומי מחקר, דרגות)     • שיוך עובדים למחלקות           • ישות חלשה תלויה       • השתלמויות פדגוגיות
  • סגל מנהלי (משרדים,     • מניעת מחיקת מחלקה             • אימות זמנים יומי      • מעקב הסמכות רב-פעמי
    דרגי ניהול, תפקידים)     פעילה (RESTRICT)              • בקרה על שעות עבודה    • קשר רבים-לרבים (M:N)
```

1. **עובדים והתמחות סגל (Staff & Subtypes):**  
   שימוש במודל ירושה רלציוני (Supertype/Subtype) מסוג Table-per-Type. כלל הנתונים המשותפים (ת"ז, שכר יסוד, תאריך תחילת עבודה, שיוך מחלקתי) שמורים בטבלת העל `Employee`, בעוד שדות ייחודיים נשמרים בטבלאות הבן `AcademicStaff` ו־`AdministrativeStaff` עם מפתח זר תלוי מחיקה (`CASCADE`).
2. **מחלקות ותקציבים (Departments):**  
   טבלה מרכזית `Department` המגדירה שמות מחלקות ותקציב שנתי, בקשר של 1:N מול העובדים.
3. **יומני נוכחות (Attendance Tracking):**  
   מידול כישות חלשה `AttendanceRecord` עם מפתח מורכב `(EmployeeID, RecordID)`. תאריכי משמרת וזמני כניסה ויציאה נבדקים באילוצי טווח תקינים.
4. **הדרכות וקורסים (Training Catalog):**  
   קטלוג קורסים `TrainingCourse` וטבלת קשר רבים־לרבים `Employee_Training` עם מפתח משולש `(EmployeeID, CourseID, CompletionDate)` המאפשר תיעוד היסטורי של השתלמויות חוזרות.

## 6. הוראות התקנה והרצה ראשונית (Quick Start)

### א. הפעלת סביבת Docker
הפרויקט כולל קובץ `docker-compose.yml` המרים מסד נתונים PostgreSQL ושרת pgAdmin 4 בלחיצה אחת:

```bash
# הרמת הקונטיינרים ברקע
docker compose up -d
```
* **גישה ל־pgAdmin:** בדפדפן בכתובת `http://localhost:8080`.

### ב. יצירת הטבלאות ואכלוס הנתונים
להקמת הסכמה והזנת כל 43,000 הרשומות מתוך הטרמינל (PowerShell):

```powershell
$stage = "DBProject_1532_8415\שלב א"

# יצירת סכמת הטבלאות (DDL)
docker exec -i PostgreSQL_DB psql -U postgres -d college_hr_db -f - < "$stage\createTables.sql"

# אכלוס מלא של כל הטבלאות
docker exec -i PostgreSQL_DB psql -U postgres -d college_hr_db -f - < "$stage\insertTables.sql"

# בדיקת ספירת רשומות
docker exec -i PostgreSQL_DB psql -U postgres -d college_hr_db -f - < "$stage\audit.sql"
```
